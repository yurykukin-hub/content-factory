# Урок 04 — Распил god-view: извлекай скрытую логику, не хромо

**Дата:** 2026-07-05 (Фаза D)

## Что было (боль)
Два god-компонента с ОДНИМ потребителем каждый (в отличие от студий из Урока 03, где дубль был между тремя зеркалами): `MediaLibraryView.vue` (1283 стр) и `BusinessDetailView.vue` (1030 стр). Соблазн — распилить «по разделам» на кучу подкомпонентов (`SortToolbar`/`MediaFilters`/`FolderGrid`/`MediaCard`/…) + composables на всё подряд. Но у single-consumer view нет второго зеркала → подкомпонент = просто markup-на-refs, а prop-drill (особенно горячая `MediaCard`: ~12 props/emits + прокидывание shift-range) — **net-negative**: кода больше, когезии меньше.

## Решение (работает)
Скептик-opus урезал «6 composables + 9 подкомпонентов» до минимума, который реально платит — **извлекать только скрытую, тестируемую МЕХАНИКУ, не хром**:
- **MediaLibrary → 2 composables** (1283→1192): `useStudioSSE`-**переиспользование** (была байт-копия плюмбинга студий — M1) + `useMediaSelection<T>` (машина выделения: Set + shift-диапазон + long-press — M2).
- **BusinessDetail → 3 компонента + 1 composable** (1030→**407, −60%**): `StoryTemplatesPanel`+`useStoryTemplates` (B1), `AccessPanel` (B2), `ChannelsManager` (B3). Каждая фича — самодостаточна (грузит своё, эмитит наружу), потому что это ЦЕЛЬНАЯ фича, а не кусок layout.
- **Реальный LOC-выигрыш — в удалении мёртвого, не в распиле:** Ideas+ContentPlans views (~750 стр) + design-layer стек (4 файла + endpoint). Распил ≈ LOC-нейтрален (код переезжает). Продаём распил как **когезию+тестируемость**, не как «уменьшили кодовую базу».

## Грабли/follow-up (поведение-сохраняюще → характеризация до/после на КАЖДОМ шве)
1. **`useMediaSelection` — reassign-not-mutate (макс.риск).** Каждый путь присваивает НОВЫЙ `Set` (`selectedFiles.value = new Set(...)`), иначе computed не пересчитываются. Двигать логику ДОСЛОВНО; единственная правка — `displayedFiles.value[k]`→`displayedFiles()[k]` (геттер-инъекция). **Тайтовая граница:** извлёк только машину выделения (2 инъекта: displayedFiles-геттер + previewFile-ref); bulk-действия (delete/move + диалог) ОСТАВИЛ во view (6 инъектов, если тащить их тоже) — они читают `selectedFiles`/`clearSelection` из composable.
2. **`AccessPanel` — `$refs`→`v-model` меняет поведение (единственная смена во всей фазе).** Нативный `<select>` без v-model даёт дефолт = первая опция, которую читал `$refs.addUserSelect.value`. Наивный `v-model="ref('')"` → кнопка no-op на первом клике (регрессия). Фикс: `watch(usersWithoutAccess, …, {immediate:true})` держит `selectedUserId` = первому доступному → воспроизводит нативный дефолт. Сначала фикс на месте (B2a, отдельный коммит), ПОТОМ извлечение (B2b).
3. **`ChannelsManager` — emit-контракт для родительского reload.** Функции, звавшие `loadBusiness()`, теперь `emit('changed')`; родитель `@changed="loadBusiness"`. Модалка добавления была root-sibling (не вложена в таб) — переехала в компонент ВМЕСТЕ с триггером. `isAdmin` пришлось re-derive в компоненте (перенесённый markup гейтит на нём в 5+ местах).
4. **Характеризация до/после = страховка от тихой регрессии.** Playwright-скрипт прогонял ИДЕНТИЧНУЮ последовательность до и после: выделение (plain=1/shift=4/ctrl 4→3→4/Esc→0), grant/revoke (реальные dev-юзеры, outcome-based: юзер переезжает между списками = PUT businessIds верный), каналы (dummy-канал add→«Каналы(1)»→delete→«(0)»). Совпадение 1:1 → шов принят; иначе откат.
5. **Тайминг v-model в автоматизации:** `.fill()` СИНХРОНИЗИРУЕТ Vue-модель (диспатчит `input`), но `:disabled` читать надо в СЛЕДУЮЩЕМ вызове (Vue флашит на nextTick). Ложная тревога «v-model не синкается» = на деле пропущенное 3-е обязательное поле (кнопка add требовала accountId, гард функции — нет).
6. **B4 (useBusinessChannels/useBrandProfile) НЕ делали** — после B1-B3 BusinessDetail = 407 стр, уже не god. Defer по факту, не по недосмотру.

## Вывод для делегирования
Для **single-consumer** god-view спрашивай не «на какие разделы порезать», а «какая тут СКРЫТАЯ повторяющаяся/тестируемая механика (SSE, selection-стейт-машина, CRUD-фича)?» — её и выноси. Layout-хром и горячие prop-drill ячейки (`MediaCard`) НЕ трогай — подкомпонент там net-negative. Механику — на sonnet (структурный вынос по тайтовому спеку), selection-/$refs-чувствительные швы — сам с Playwright-характеризацией до/после и коммитом по шагу. Реальную экономию строк ищи в удалении МЁРТВОГО, а не в распиле.
